# 白盒告警导入与人工复核

在 **功能 → 白盒复核** 粘贴告警 JSON，或上传白盒报告文件。列表按应用分组，展开应用后可以查看该应用的告警。打开告警可以查看源码上下文和复核材料，并保存人工复核结论与说明。

## 导入单条告警

`POST /api/validation/alerts` 沿用 ARTEX 的管理端认证。以下为最小示例。

```json
{
  "source": "internal-sast",
  "scan_id": "scan-001",
  "external_id": "finding-001",
  "title": "日志字段待复核",
  "vulnerability_type": "CWE-532",
  "context": {"app_id": "example-app"}
}
```

按 `source + scan_id + external_id` 去重。第一次保存返回 HTTP 201，相同内容再次导入返回 HTTP 200，身份相同但内容发生变化时返回 HTTP 409。

## 导入批量报告

`POST /api/validation/imports/sast-report` 接收顶层带 `findings` 的 JSON，也支持 `{"code":0,"data":{"findings":[...]}}`。可以用 `{"submit":false,"report":{...}}` 预检，用 `{"submit":true,"report":{...}}` 保存。单次最多 500 条和 5 MiB。报告中的 `jobId` 对应扫描批次，`findings[].id` 对应原告警。没有批次 ID 时，ARTEX 会生成本地批次。

应用分组优先从 `repoURL` 的最后一段推导。问题代码和 PoC 文本通过告警详情展示。导入会遮盖报告通过 `secretValue` 明示的敏感值，单份材料最多保留 16 KiB。

## 记录人工复核

`POST /api/validation/alerts/{id}/reviews` 保存一条人工复核。请求体示例为 `{"result":"uncertain","note":"缺少对应部署版本的证据"}`。支持 `vulnerability_exists`、`false_positive` 和 `uncertain`，复核说明必填。 `GET /api/validation/alerts/{id}` 返回告警及最近 100 条复核记录。
